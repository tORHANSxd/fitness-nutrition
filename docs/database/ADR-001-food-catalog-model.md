# ADR-001：食物目录模型

## 状态

已接受，采用短期低风险方案 A。

## 背景

现有应用同时存在代码内 `builtinFoods`、`foods` 用户食物、历史计划 ID 引用和 `food_overrides`。直接拆成多张公共目录表会扩大迁移面，且不能自动恢复已经删除的用户食物。

## 决策

- `builtinFoods` 是当前公共食物目录真源，公共文本 ID 必须保持稳定。
- `foods` 新写入只保存用户食物；删除改为设置 `archived_at`。
- `food_overrides` 保存用户对内置公共食物的覆盖。
- 新计划、草稿和模板必须内嵌 `FoodSnapshotV1`。
- 当前编辑优先实时食物；已保存计划统计优先保存时快照；缺失快照与实时食物时标记 `unresolved_food_ref:<id>`，不得按 0 冒充完整结果。
- 数据库中既有的 `user_id is null` 公共食物仅在兼容期读取，本轮不物理删除。

## 结果

软删除和快照先解决数据完整性，避免本轮同时迁移分类枚举、翻译和所有引用。代价是兼容期仍有两种公共食物来源，读取层必须去重。

## 后续

只有在完成真实行数审计、公共 ID 映射和一个稳定发布周期后，才单独评估 `public_foods`、翻译表和稳定分类代码。该拆分不属于本轮。
